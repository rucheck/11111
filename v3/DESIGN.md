# 盐选人生：90天写作生存战 —— 内容生产契约（DESIGN.md）

本文档是各内容 agent 的唯一权威 schema 来源。所有 agent 必须严格按本文档输出**合法 JSON**（UTF-8、无 BOM、无尾逗号、中文全角标点），写到指定路径，并在回复里返回「文件路径 + 关键数量 + 自检说明」。

## 0. 游戏是什么（给 agent 的上下文）

玩家扮演知乎盐选写手，90 天倒计时内从一道知乎风格热门问题出发，连载一部小说。
- **外层作者**：定本章剧本（具体度 具体/适中/宽泛）、看数据、读评论、做作者层决策。
- **内层主角**：进入章节场景，做故事决策；AI 据此「续写」章节，发布后 AI 读者生成有立场、有记忆的评论，反作用于下一章。
- 结局同时结算「作品结局」与「作者结局」。

## 1. 规范常量（所有文件必须复用这些枚举值，逐字一致）

- 类型标签 genre（6）：`悬疑反转` `都市情感` `女性成长` `民俗怪谈` `职场冲突` `历史脑洞`
- 核心主题 theme（5）：`真相` `尊严` `牺牲` `亲密关系` `现实困境`
- 创作路线 route（5）：`流量路线` `质量路线` `争议路线` `商业路线` `自我路线`
- 阶段 stage（4）：`起步期`(90-61) `增长期`(60-31) `危机期`(30-11) `收束期`(10-0)
- 资源 resource（6）：`行动力` `精力` `热度` `质量` `作者风格` `签约概率`
- 读者 archetype（7）：`催更党` `杠精` `剧情分析帝` `代入型读者` `CP党` `价值观审判者` `真爱读者`
- 结局（7，见 endings.json）：`盐选签约作者` `爆款制造机` `坚持表达者` `争议作家` `高产但疲惫的作者` `AI依赖者` `未签约但留下作品的人`

## 2. 占位符（placeholders）

引擎会在「续写正文」「评论」「结局文案」里做字符串替换。agent 可在文本中使用下列 `{token}`，**不要使用其它花括号**：

`{protagonist}` 主角称呼 · `{npc}` 关键NPC名 · `{npc2}` 第二NPC名 · `{place}` 场景地点 · `{theme}` 主题词 · `{goal}` 本章目标短语 · `{decision}` 玩家所选行动 · `{cliff}` 章节悬念短语 · `{route}` 路线名 · `{genre}` 类型标签

引擎对无值 token 会替换为通顺的默认词，所以允许少量缺省，但尽量提供可填词。

## 3. 数值效应约定

所有 `effect` 对象字段：`heat`(热度) `quality`(质量) `energy`(精力) `sign`(签约概率)，均为整数，范围 **-3 ~ +3**；`style`(作者风格，正=坚持自我/负=迎合漂移) 范围 **-5 ~ +5**。缺省视为 0。

## 4. 文件清单（agent 各写其一）

| 文件 | 负责 agent | 顶层结构 |
|---|---|---|
| `game/content/questions.json` | A1 | `{"questions":[...]}` |
| `game/content/story.json` | A2 | `{"genres":{...},"crisis":{...}}` |

## 5. 各文件精确 schema

### 5.1 questions.json（题库，12 道）
覆盖 6 个 genre 各 2 道，theme 尽量分布到 5 个。字段：
```
{
 "id": "q01",
 "title": "知乎风格问题标题（要像真实热榜问题，带悬念/情感张力）",
 "genre": "悬疑反转",            // 必须是上面 6 个之一
 "theme": "真相",                // 必须是上面 5 个之一
 "hook": "开篇一句话，半写实都市剧场的画面感（人物+异常细节）",
 "premise": "2~3 句：主角处境 + 核心冲突 + 贯穿悬念",
 "protagonist": {"role":"主角身份","want":"想要什么","secret":"软肋/秘密"},
 "npc": [{"name":"…","role":"与主角关系","goal":"动机或秘密"}],   // 2~3 个
 "setting": "都市具体地点（地铁站/老小区/写字楼/出租屋…）",
 "mystery": "贯穿全篇的悬念（一句话）"
}
```

### 5.2 story.json（叙事原子库）
结构：
```
{
 "genres": {
   "<每个 genre 标签>": {
     "chapterGoals": ["短语目标", ...],          // 5~6 条，如「揭露一条关键线索」「制造一次反转」
     "scenes": [{"name":"地点名","desc":"画面化场景描写一句","mood":"情绪词"}],  // 5 条
     "decisions": [                              // 6~8 条，主角行动选择
       {"text":"行动短语","effect":{"heat":0,"quality":0,"energy":0,"style":0,"sign":0},"consequence":"选择后的即时结果（含占位符）"}
     ],
     "openings": ["续写开篇句，含占位符"],        // 4~6 条
     "bodies": ["续写正文段，含占位符"],          // 6~8 条
     "cliffhangers": ["悬念收尾句，含占位符"]     // 5~6 条
   }
 },
 "crisis": {
   "complications": ["危机期突发状况句，含占位符"],  // 5~6 条
   "finalChoices": [                                // 4 条最终抉择
     {"text":"…","effect":{...},"consequence":"…"}
   ]
 }
}
```
要求：`decisions` 的行动要与该 genre 强相关（如悬疑：质问/暗中调查/报警/设局；职场：硬刚/隐忍/站队/甩锅），且 effect 有正有负、有取舍。

### 5.3 readers.json（AI 读者评论模板）
```
{
 "readers": [
   {
     "id": "催更党",           // 7 个 archetype 各一条
     "persona": "一句话人设",
     "weight": 1.2,            // 出现权重，0.3~1.5
     "templates": [            // 3~4 条评论模板，含占位符，评论须「具体回应刚发布内容」而非空泛
       "就卡在{cliff}这里断了？{decision}之后到底怎么样，快更！"
     ]
   }, ...
 ]
}
```

### 5.4 editor.json（AI 编辑）
```
{
 "intro": "编辑首次介入的开场白（有压迫感但克制，含占位符）",
 "demands": [
   {
     "id": "d1",
     "stage": "增长期",                       // 4 阶段之一
     "condition": {"heat":{"lt":40}},         // 可选；省略=该阶段恒可触发
     "text": "编辑要求的一句话（含占位符）",
     "constraint": "成为下一章写作约束的一句话",
     "effect": {"sign":0,"style":0}
   }, ...
 ]
}
```
`condition` 支持键：`heat` `quality` `energy` `sign`，值为 `{"lt":N}` 或 `{"gt":N}`。要求：4 个阶段各至少 1 条，且覆盖「加冲突/强爽点/加感情线/降价值观风险/稳定更新/传播性结局」等真实编辑话术。

### 5.5 endings.json（结局）
```
{
 "endings": [
   {
     "id": "signed",
     "title": "盐选签约作者",
     "subtitle": "一句定调",
     "condition": {"heat":{"gte":70},"quality":{"gte":60},"sign":{"gte":60}},  // 可多键，全满足才命中；default 结局省略
     "priority": 10,                          // 数字越大越先判定
     "default": false,
     "archive": {
       "verdict": "作者生涯判词（1~2句）",
       "styleLine": "风格分析一句",
       "traits": ["标签1","标签2","标签3"],
       "afterword": "作者后记段落（2~4句，第一人称，含占位符）"
     },
     "cover": {"title":"作品名","tagline":"封面腰封一句","spine":"书脊小字"}
   }, ...
 ]
}
```
必须恰好 7 条、id/title 与第 1 节枚举一一对应；其中 `未签约但留下作品的人` 设为 `"default": true` 且无 condition。

### 5.6 events.json（随机突发事件）
```
{
 "events": [
   {
     "id": "ev1",
     "name": "角色失控",
     "desc": "一句话事件描述（含占位符）",
     "effect": {"heat":0,"quality":0,"energy":0,"sign":0,"style":0},
     "comment": "伴随的一条读者评论（含占位符）"
   }, ...
 ]
}
```
覆盖 4 类：`角色失控` `伏笔暴露` `评论出圈` `旧文翻红`，每类 2 条共 8 条。

## 6. 语言与合规

- 全部中文，知乎气质：讲逻辑、讲证据、讲现实经验、谈价值观与叙事结构。
- 原创撰写，**不复制任何真实盐选/知乎具体文章内容**；人物、情节、评论均为自造。
- 输出必须是**单一合法 JSON 文件**，不要 markdown 代码块包裹，不要额外文字（说明放回复里，不要放进文件）。

## 7. 交付与自检

每个 agent 完成后：
1. 用 `write` 工具把 JSON 写到指定路径。
2. 在回复里返回：`文件路径`、`顶层数组长度`、`自检：已覆盖哪些枚举/占位符`。
3. 若无法确定字段，优先保证 JSON 合法且枚举值逐字一致，宁缺勿错。
