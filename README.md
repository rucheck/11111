## 游戏简介

这是一款**元叙事互动游戏**——你扮演的不是小说主角，而是**写小说的人**。

**外层（作者层）**：你是一个刚入驻知乎盐选的新人作者，有 90 天（假想）时间完成一部连载。你需要选择创作路线、规划章节、应对编辑的修改要求、阅读和分析读者评论。

**内层（故事层）**：你笔下的小说主角在故事世界里做出决策——追查线索、做出选择、面对冲突。系统会根据你的创作路线和主角选择，自动生成续写正文。

最后，游戏同时结算两件事：**作品结局**（故事本身收得如何）和**作者结局**（你这 90 天的写作生涯走向何方）。

## 玩法说明

### 核心循环

抽题选方向 → 设置作者身份 → 进入连载地图 → 工作台（定本章剧本 + 选具体度）→ 主角进入章节场景 → 面临选择 → 做决策 → AI 续写正文 → 发布 → AI 读者评论 → 作者回应评论 → 进入下一章 → 回到工作台 …… 重复 5 章后进入危机阶段 & 最终抉择 → 结局

### 六种题材（Genre）

悬疑反转 · 都市情感 · 女性成长 · 民俗怪谈 · 职场冲突 · 历史脑洞

每次开局随机抽一道富有知乎风格的热榜问题，决定你这部小说的基调。

### 五条创作路线（Route）

| 路线 | 特点 | 颜色 |
|------|------|------|
| 流量路线 | 热门标签、强冲突、快速更新 | 红色 |
| 质量路线 | 伏笔、人物、慢热铺垫 | 蓝色 |
| 争议路线 | 灰色主题、道德冲突、出圈 | 紫色 |
| 商业路线 | 迎合编辑、强化爽点、适配盐选 | 橙色 |
| 自我路线 | 坚持原主题与个人风格 | 绿色 |

每条路线影响你获得的资源倾向和事件触发逻辑。

### 六项资源（Resource）

行动力 · 精力 · 热度 · 质量 · 作者风格 · 签约概率

你的每一个决策（主角行动 + 作者回应）都会影响这些数值，它们共同决定最后能触发哪个结局。

### 剧本具体度（Specificity）

- **具体**：指定地点、人物、目标与结果。选择少，稳定推进。消耗 15 资源
- **适中**：指定冲突、关键人物与必现事件。允许局部偏离。消耗 20 资源
- **宽泛**：只定主题、情绪与本章问题。高自由度，可能触发隐藏事件。消耗 25 资源

具体度越高，消耗的资源越多，但选择空间和潜在回报也越大。

### 四种写作阶段（Stage）

起步期（90-61 天）→ 增长期（60-31 天）→ 危机期（30-11 天）→ 收束期（10-0 天）

每个阶段编辑的要求和系统压力不同。

### 七种结局

盐选签约作者 · 爆款制造机 · 坚持表达者 · 争议作家 · 高产但疲惫的作者 · AI 依赖者 · 未签约但留下作品的人

根据你的资源积累和路线倾向，触发不同的结局。

## 游戏流程详解

### 第 1 步：开场动画
启动游戏后，先播放一段开场动画，建立知乎盐选写手世界的氛围。

### 第 2 步：抽题
系统从 12 道题库中随机抽取一道知乎风格的热榜问题，决定你这次创作的题材和主题。每道题包含完整的设定：主角身份、NPC 角色、场景地点和贯穿悬念。

### 第 3 步：设置作者身份
- 选择作品篇幅：短篇（6 章）、中篇（9 章）、长篇（12 章）
- 选择题材（或沿用抽到的结果）
- 选择主题
- 选择创作路线

### 第 4 步：进入连载地图
一张 90 天倒计时的连载地图，标注每一章的推进时间和当前所处阶段。

### 第 5 步：写作循环（每章重复）

**工作台阶段：**
- 制定本章剧本目标
- 选择剧本具体度（具体 / 适中 / 宽泛）
- 配置准备动作

**章节场景阶段：**
- 进入场景，查看情境描述
- 从多个行动中选择主角将要采取的动作
- 每个选择都有对应的数值效应（热度、质量、精力、作者风格、签约概率的变化）

**续写生成阶段：**
- 系统根据你的选择自动生成续写正文
- 正文中包含丰富的叙事占位符，运行时会替换为当前上下文的具体内容

**发布与评论阶段：**
- 发布章节后，AI 读者会生成有立场、有记忆的评论
- 读者类型包括：催更党、杠精、剧情分析帝、代入型读者、CP 党、价值观审判者、真爱读者

**作者回应阶段：**
- 置之不理 — 让子弹飞一会，节省精力，维护风格
- 回复读者 — 下场互动带热度，消耗精力
- 公开争论 — 硬刚引来争议，消耗精力但热度大涨
- 修改大纲 — 顺着反馈微调走向，牺牲部分风格
- 迎合评论 — 按读者想要的方向写，热度上升但风格漂移
- 坚持原计划 — 不改，写完再看，维护风格但热度可能下降

### 第 6 步：编辑干预
游戏过程中，编辑会根据阶段和条件主动提出写作要求，作为下一章的硬约束。满足编辑要求会提升签约概率，但可能影响你的作者风格。

编辑会在以下时机介入：
- **起步期**：热度不足时强制增加前期冲突；或要求稳定更新节奏
- **增长期**：热度涨粉期要求安排反击场面；或签约概率偏低时要求加入感情线
- **危机期**：热度太高要求降风险；精力不足要求保更新；质量偏低要求砍支线
- **收束期**：要求写出可传播的收尾句；或约束结局的表达安全区间

### 第 7 步：随机事件
写作过程会触发随机事件，包括：
- 角色失控（正负效应都可能）
- 伏笔暴露（影响读者预期）
- 评论出圈（热度暴涨但伴随争议）
- 旧文翻红（涨粉也可能被挖旧账）

每种事件有正负效应，并附带一条配套的读者评论。

### 第 8 步：危机与最终抉择
第 5 章结束后进入危机阶段，主角面临最终抉择，决定故事的走向和结局基调。

### 第 9 步：结局
游戏根据你的数值积累和综合表现结算结局，展示：
- 作品封面（书名、腰封、书脊）
- 作者生涯判词
- 风格分析
- 作者后记
- 完整数值报告

## 技术栈

- **纯前端**：HTML5 + CSS3 + Vanilla JavaScript（零框架、零依赖）
- **美术风格**：编辑部现实主义 — 米色纸张底色、宋体为主、克制色彩。CSS 变量集中管理配色
- **构建**：Node.js 脚本（build.js），将源文件和 JSON 内容打包为自包含单页面 HTML
- **存储**：浏览器 localStorage（自动存档，刷新不丢进度）
- **可选集成**：知乎 CLI（通过 server.js 提供知乎直答生成能力，每日 5000 次限额）

## 内容系统说明

游戏的全部叙事内容以 JSON 文件存储在 content/ 目录，严格遵循 DESIGN.md 定义的数据契约。所有文件使用 UTF-8 编码、中文全角标点、无尾逗号。

### 数据结构一览

| 文件 | 内容 | 规模 |
|------|------|------|
| questions.json | 知乎风格问题题库，每道含完整的人物设定和悬念 | 12 道 |
| story.json | 每个题材的场景库、决策池、开场句、正文段、悬念句 | 6 种题材 × 多组模板 |
| readers.json | AI 读者评论模板，按 7 种读者类型分组，含出现权重 | 每种类型 3-4 条模板 |
| editor.json | 编辑开场白 + 各阶段写作约束需求，含触发条件 | 4 阶段共 10 条 |
| endings.json | 结局标题、条件、优先级、判词、封面文案 | 7 种结局 |
| events.json | 随机突发事件，含名称、描述、效应和配套评论 | 4 类共 8 条 |

## 测试与验证

### 冒烟测试（test.js）

在无头 DOM 环境下模拟 80 轮完整对局，覆盖：
- 所有篇幅组合（短篇 / 中篇 / 长篇）
- 所有题材和路线组合
- 完整游戏流程：标题 → 开场 → 模式选择 → 抽题 → 设置 → 地图 → 5 章写作循环 → 危机 → 结局
- 每章验证：工作台渲染、场景与决策界面、续写正文、评论列表、作者回应
- 最终验证：危机界面、结局封面 + 作者档案 + 数值报告

```powershell
node test.js
# 期望输出：done: 80 runs, 0 failures
```

### 流程抽查（inspect.js）

执行一次完整对局并输出关键环节的文字内容，同时扫描全页检查是否存在未被替换的占位符泄漏。

```powershell
node inspect.js
# 输出：抽取的题目、章节目标、场景、选项、续写正文、评论、结局、泄漏检查结果
```

### 存读档测试（save.test.js，v2 版本）

覆盖 5 种场景：
- A. 刷新后由标题页选择继续，章节、选择、资源和剧情状态一致
- B. 关闭再重开，恢复同一中途状态
- C. 完成一章进入下一章后恢复，跨章记忆和历史选择保持一致
- D. 新游戏替换旧存档，所有跨局状态归零
- E. 损坏、缺字段、不兼容和不可用的 localStorage 均安全回到标题页

## 开发协作

### 添加/修改游戏内容

编辑 content/ 目录下对应的 JSON 文件，然后重新构建：

```powershell
node build.js
```

编辑时注意：
- 保持 JSON 合法（无尾逗号、UTF-8 编码）
- 枚举值必须与 DESIGN.md 中的规范常量逐字一致
- 占位符使用 `{xxx}` 格式，不要使用其他花括号

### 添加新题材

1. 在 questions.json 中增加对应题材的题目（至少 2 道）
2. 在 story.json 中增加该题材的 scenes / decisions / openings / bodies / cliffhangers
3. 在 app.js 的 GENRES 常量中注册新题材标签
4. 运行 test.js 和 inspect.js 验证通过



### PR 与合并流程

1. 在分支上完成修改后，先运行 `node build.js` 确认构建通过
2. 运行 `node test.js` 和 `node inspect.js` 确认测试全绿
3. 提交 PR，说明修改范围和影响
4. 合并后更新 README 中的版本说明

## 常见问题

### 怎么选择篇幅？

短篇 6 章 × 4 幕，中篇 9 章 × 5 幕，长篇 12 章 × 6 幕。篇幅越长冲突越密集，建议首次游玩选择短篇熟悉流程。

### 怎么存档？

游戏会在关键决策后自动保存到浏览器 localStorage。刷新或关闭页面后，从标题页可以选择「继续游戏」恢复进度。进度以 `yanxuan-life.save.v1` 为键名存储。

### 什么是「知乎模式」？

知乎模式通过知乎 CLI 调用知乎直答生成章节内容，提供更丰富的续写体验；本地模式使用内置内容模板，不联网且不限次数。首次运行选择「本地模式」即可完整游玩全部内容。

### 构建时遇到问题？

确保 Node.js 版本 ≥ 18。本项目无 npm 依赖，无需执行 npm install。如果 build.js 报错，检查 content/ 下所有 JSON 文件是否合法（无尾逗号、UTF-8 编码、全角标点）。

### 如何参与贡献？

请先阅读 DESIGN.md 了解数据契约规范，然后通过 Pull Request 提交修改。建议先运行 test.js 和 inspect.js 确认没有破坏现有功能。
